# AGENTS とスキルの設計指針

## 文書の役割

AGENTS.md は、AI エージェントが対象ディレクトリで作業を始めるための入口です。  
詳細な規範や設計を重複して記載せず、対象固有の制約、必須参照先、変更時に同時確認するファイルを示します。

README.md は、人間がディレクトリの目的と主要入口を把握するための文書です。  
ビルド方法、成果物、発行ドキュメントなど、利用開始に必要な情報を示します。

通常のドキュメントは、規範、設計、手順の唯一の詳細記載箇所です。  
同じドキュメントを複数の AGENTS.md や SKILL.md から参照して構いません。

SKILL.md は、特定作業の発火条件、判断基準、必要な制約を示します。  
判定表、長い例、規範本文は通常のドキュメントへ置き、SKILL.md には再掲しません。

## 参照順

`AGENTS.md` の適用範囲と参照順は、ルート [AGENTS.md](../../../AGENTS.md) を正本とします。  
対象パス上に存在する `AGENTS.md` を、ルート側から順に、上位からの差分として重ねて適用します。

適用範囲は、Git の境界ではなくディレクトリ階層で決まります。  
サブモジュールは、独立して開発とコミットを行うための単位であり、規則の適用範囲を区切る単位ではありません。  
同じ場所にある同じ種類のソースが、サブモジュールかどうかで別の規則に従うと、作業者は適用される規則を予測できません。

下位の文書は、上位の規則を対象固有に具体化し、上位に無い条件を追加します。  
上位の規則を解除または上書きする場合は、解除する規則と理由を明示してください。  
明示のない相違は、上位の規則が有効なままです。

`AGENTS.md` の存在確認では、戻り値を非 0 にしないでください。  
`AGENTS.md` が無い階層は走査上の正常な状態であり、非 0 の戻り値は不要なエラー表示を招きます。

## 配置

- すべての `app/<name>` 直下に `AGENTS.md` と `README.md` を配置します。
- より深い階層にも `AGENTS.md` を配置できます。配置したディレクトリ配下が、その文書の適用範囲になります。
- framework 固有の規則とスキルは、その framework のルート ディレクトリに配置します。
- 全 app に共通するスキルは `app/general/.agents/skills/` に配置します。
- 個別 app のスキルは、その app の `.agents/skills/` に配置します。
- ワークスペース構成や CI に固有のスキルは `app/<workspace>/.agents/skills/` に配置します。
- ルート `.agents/skills/` は `make skills` の射影先であり、追跡対象のスキル正本を直接配置しません。

## 依存方向

汎用層は、利用側の具体的な実装を規範や必須例として参照しません。  
framework の文書では `app/example` などの架空名を使い、実在 app のパスを正本にしません。  
`app/general` も、個別 app 固有の設定を保持しません。

個別 app から `app/general`、framework、実際に利用する別 app を参照することはできます。  
この方向により、汎用層を別のワークスペースでも利用できます。

## AGENTS.md の内容

AGENTS.md には、次の情報だけを記載します。

- 対象の目的と範囲
- 作業の種類に応じて参照する文書と節
- 主要なソース、テスト、生成物の入口
- 対象固有の変更トリガーと同時更新先
- 対象固有の確認コマンド

一般的な技術解説、長いコード例、他の文書に存在するチェックリストは記載しません。

範囲の既定は、その `AGENTS.md` が置かれたディレクトリ配下です。  
既定と異なる範囲を対象にする場合だけ、対象範囲を明記します。

上位の規則の再掲は、二重管理になるため通常は行いません。  
単独で clone して利用するリポジトリでは、自己完結のための再掲を許容します。  
その場合も、上位と矛盾する内容を書かないでください。意図して異なる規則にするときは、解除する規則と理由を明示します。

## SKILL.md の内容

管理対象の frontmatter は `name` と `description` を基本とします。  
既存の対応済みメタデータは、その用途を確認して保持してください。  
Windows の生成コピーに付与される `git-origin` は発行用の例外であり、正本へ転記しません。  
`description` は機能と発火条件を簡潔に示し、選択に不要なチェック項目の列挙を避けます。  
本文には、参照する正本の該当節と、それを読む条件を示します。

同じ詳細を SKILL.md と通常文書の双方へ記載しません。  
対象固有の例外がある場合は、より狭いスキル、または対象パス上のより下位の `AGENTS.md` を優先します。

## 指示の粒度と完了条件

モデルが通常判断できる一般手順より、配置、ABI、生成物、リンクなどの固有条件を優先します。  
固定の順序は、順序を変えると具体的な問題が生じる操作に限定します。  
短いスキルは自己完結のままでよく、分岐がない手順のために補助文書を増やしません。  
大きな文書は見出しや検索語から必要な節を選び、参照先全体の読み込みを要求しません。

レビュー、調査、変更を区別し、読み取りだけの依頼から更新操作へ進ませないでください。  
検証は変更の影響とリスクに応じて選び、同じ結果の重複取得を要求しません。  
変更作業の完了条件には、必要な局所検証と変更起因の失敗修正を含めます。  
外部公開や全体テストなどの確認条件と、許可された範囲で継続できる作業を区別します。  
明示されたユーザーの許可境界を、モデルの能力を理由に解除しません。

環境依存の回避策には発生条件を付け、対処の詳細は通常文書へ置きます。  
個別 app の専用スキルへの振り分けは、その app の指示に置きます。  
汎用スキルからは対象パスの専用手順へ案内し、任意の個別 app が存在することを前提にしません。

## 日本語の文体

本文段落は、です・ます調で記載します。  
見出し、短いリスト項目、表のセル、コード、引用では、名詞句や常体を使用できます。  
一文一行とし、表示幅を理由に文の途中で改行しません。
