## リポジトリ概要

固定レコード長バイナリ ファイルに対して、`com_util` の `stdio` ラッパー API とメモリ マップド ファイル API の性能を比較するベンチマーク コマンドです。
測定結果の CSV は `docs/measurements/` へ出力しますが、このディレクトリは `docs/.gitignore` で管理対象外です。
リポジトリで共有する成果は `docs/api-selection-guideline.md` であり、CSV から必要な数値を転記して維持します。

## 作業時の入口

- `prod/src/cmd/bench-io/` - ベンチマーク本体
    - `bench-io.c` - エントリ ポイント、コマンドライン解析、ケース列挙、実行制御
    - `bench_case.h` - レコード型、ケース記述子、API 実装の共通インターフェース
    - `bench_timer.h` / `bench_timer.c` - 反復回数の自動調整と所要時間の集計
    - `bench_stdio.c` - `stdio` ラッパー API による各パターンの実装
    - `bench_mmap.c` - メモリ マップド ファイル API による各パターンの実装
    - `bench_report.c` - 環境情報の収集と CSV / テーブルの出力
- `docs/` - 測定方法、選定基準、測定結果

## 主要コマンド

```bash
make
./prod/cbin/bench-io --help
```

## 注意点

- 本 app には `test/` を置いていない。測定に時間がかかり CI を圧迫するため、`make test` の対象にしない。
- 測定軸 (API 形態、アクセス パターン、ファイル サイズ) を変更した場合は、`docs/benchmark-method.md` の表と `docs/api-selection-guideline.md` の結論を同時に見直すこと。
  測定条件が変わると過去の測定値と比較できなくなるため、実測をやり直したうえで `docs/api-selection-guideline.md` の表を更新すること。
- 測定値は環境に強く依存する。CSV には OS、CPU、ファイル システム種別、ページ キャッシュの状態が記録されるので、結果を引用するときは必ずこれらを添えること。
  CSV 自体はリポジトリに残らないため、引用元の測定環境は `docs/api-selection-guideline.md` の「測定条件」に必ず記録すること。
- 新しいレコード型やアクセス パターンを追加するときは、レコード構造体にパディングが入らないことを確認すること。
  ビルドは `-Wpadded` を有効にしているため、パディングが入ると警告になる。
- `com_util` に `setvbuf` のラッパーがないため、ブロック単位アクセスは自前バッファーへの読み書きで実現している。
  CRT のバッファー サイズは既定のまま変更していない。
